# 结论账本

## 生成链路

```text
已绑定证据 → 预算选择与连续原文 → 模型输出结论 JSON
                                  → 本机校验 → Markdown 报告 + 结论账本
```

完整工作流的关系分析与人物侧写各自生成 `chat-claims-v3` 账本，由程序将合格结论渲染为正文。初始材料未覆盖候选锚点所需邻文时，关系报告先调用完整脱敏原文规划，再按命题检索完整会话，两份报告共用查询和公共材料。两份新报告均须通过独立模型复核，非检索路径的空动作数组也触发复核。

检索路径直接依据入选完整会话、程序统计和覆盖记录生成两份报告。旧证据解释、阶段总结、关系报告的二手解释以及规划命题正文从该路径的生成材料移除，人物侧写独立归纳。规划命题与查询保存在带指纹的检索记录中，生成材料仅显示覆盖计数。失误与冲突要求分别说明实际行为、主体、影响、道歉和补救结果，前后回应有变化时保留时间过程。非检索路径继续使用结构化证据、阶段总结和人物侧写的关系报告线索。

模型响应使用一个完整 JSON 对象，不再要求在 JSON 外附加完成标记。客户端仍拒绝服务端报告的 `finish_reason=length`，解析器拒绝不完整 JSON、附加正文和不合格结论。程序生成的 Markdown 报告仍保留完成标记，用于产物审计；旧尝试记录中带末尾标记的 JSON 仍可重新审计。

网页“技术附件”可下载“关系结论账本”和“人物结论账本”。命令行输出位于对象临时目录的 `claim_ledger_analysis.json` / `claim_ledger_persona.json`，跟随 `analysis/` 忽略。两份报告仍以短角标回查原文。

使用命题检索的账本附加 `retrieval` 记录（`claim-retrieval-v1`），保存命题、双向查询、命中及省略原因、实际入选位置、完整会话边界、预算和来源指纹。编译及审计核对这些记录与实际报告输入。

完整会话中的文本及引用消息使用 `P_序号` 短引用，编译时确定性转换为该快照的稳定 `M_` 编号，可由网页回查。摘要未列出的旧 `E_` 编号，仅在其逐字绑定重新核验通过且对应完整原文可见时转换为 `M_`。原文引用要求完整连续语境。审计逐条核对短引用、说话人、时间和正文。

正常入口逐条请求独立复核，每个叙述字段分别检查内容是否有依据、自己的引用是否齐全、原话确定程度是否保留、会改变当前判断的已知后续是否完整交代。实际失败和再次纠错须进入判断，真正未知的外部结果可以保留存疑。每项动作核对主体、对象和状态，每项实际反证核对是否直接相反。任一检查为false即要求修订，缺项、重复、未知项目及类型错误均拒绝，整体处理结果由程序计算。

合格记录以 `claim-field-review-v2` 保存于 `semantic_review`，绑定结论与实际输入摘要值，并记录每条复核材料指纹。审计重新检查全部字段、动作及反证覆盖。实际报告输入带v2逐字段门槛时，缺失或降级记录会阻止发布。旧 `claim-field-review-v1` 和 `claim-semantic-review-v1` 记录继续按其原输入和协议审计，显式来源归属实验使用原整份复核入口。

检索报告的复核原文按消息序号固定排列，保留全部入选会话，供查找遗漏的相反事实。公共原文之后列出当前引用所属会话的位置和重复文案邻文，避免每换一条结论就重排整份材料、丢失服务端前缀缓存机会。非检索报告保留生成阶段的原文窗口和覆盖说明。复核视图将动作人物字段标为 `quote_actor` 与 `quote_target`，明确保存原话指代。原话由对方发送时，其中的我可为正确逐字主体，账本继续使用 `actor` 与 `target` 字段。

长引文有重复发送时，程序补入实际发送位置及前后基准邻文，补充材料预算24,000字节，未展示次数单独记录。全源同文计数按完整消息计算，实际情绪与语用含义仍需判断。

复核输入保留每条的counter_review状态。not_found_in_selected将未发现反证的说明限定在本次入选材料，判断正文对全量作出的否定仍须另查覆盖。

复核同时收到生成阶段实际可见的全局统计和覆盖说明，频次趋势按相应指标核查。检索原文的重复文本另显示全源逐字相等次数和本发送方次数，包含未入选会话。计数说明独立使用最多4,000字节，按文本长度优先展示并列出省略数，完整会话选材先完成。重复发送的原创性与情绪含义仍由语境判断。旧整份复核协议中，模型给出 `pass` 但实际反证检查为 `false` 时，程序按 `revise` 反馈具体问题并进入有界修订，存量审计仍严格拒绝此类矛盾记录。

逐字段复核每次处理一条结论，模型返回字段名、动作序号及反证编号，程序绑定稳定 `C_` 编号。原文消息引用使用 `P_序号`，旧证据片段在复核视图中使用 `Q_序号` 并保留来源，保存时还原实际证据编号。旧整份协议的 `R_序号` 和完整编号响应仍可按原记录核对。

修订反馈保留失败字段、动作序号或实际反证编号，并列出未通过的检查项及原理由。复核专用的临时反证编号会还原为生成器可用的证据编号，避免修订时无法定位引用。

初稿有一次格式纠错，语义修订最多一次，语义修订另有一次格式纠错。修订纠错保留最近合并内容及原失败条目范围，反馈实际可用的时间端点。错误说明列出缺失和未知字段，时间错误指出具体字段及命中词，并在修订输入末尾再次列出全部待消除错误。语义复核标明原结论序号，模型在 `revisions[].changes` 中返回每个失败条目的完整字段，程序拒绝局部字段补丁、遗漏必填字段、重复、未知字段或修改其他条目。改写判断后重新评估全部支持、反证和限制，避免残留旧反证目标。合并后重新执行完整校验与语义复核。所有实际输入、原响应、合并结果和错误分别留存，任一未通过项阻止发布。

每条独立复核响应若有JSON或检查字段错误，可按具体错误重发一次该条的完整检查。原响应、错误、纠正输入及响应分别留存，内容上的修改意见继续进入语义修订或阻止发布。已核验MiMo官方接口的 `mimo-v2.6-pro` 在该阶段使用JSON object模式，应用继续严格校验字段和覆盖。传输失败沿用客户端策略。

同一次报告生成与修订中，复核指令和实际材料完全相同时复用检查结果，记录缓存来源。文字、引用、原文或统计变化时重新复核，缓存结果也须重新通过协议校验。既有失败结果同样保留，避免重复请求偶然放行同一份草稿。明确存疑允许没有支持引用，单纯声明结果未知无需虚构证据，仍断言具体动作的文字须有自己的引用。

## 数据字段

账本保存输入快照 `source_id`、报告类型、实际报告输入的 SHA-256、本次入选证据编号、完整回填上下文的编号及非空的 `claims`。条数由独立证据决定，提示通常选择6—10条关键结论，素材少时可更少。逐条校验全部结论，合并重复判断，省略缺少依据的维度。

| 结论字段 | 含义 |
|---|---|
| `claim_id` | 程序根据快照、报告类型和结论内容生成的稳定编号 |
| `section` / `text` | 报告章节和结论文字 |
| `kind` | `fact`、`inference`、`hypothesis`、`uncertain` |
| `subject` | 对方 `peer`、互动 `interaction`、用户 `user` |
| `supporting_evidence` | 支持证据的完整编号数组 |
| `counter_evidence` | 反证对象数组：`evidence_id`、当前判断中被削弱的原样片段 `target`、相关性说明 `reason` |
| `limiting_evidence` | 情境限制对象数组：`evidence_id` 和说明适用条件的 `reason` |
| `counter_review` | `found`、`not_found_in_selected`、`not_assessed` |
| `scope` | 局部 `local`、重复 `repeated`、长期 `long_term` |
| `confidence` | 模型判断的高/中/低等级，不是概率或原抽取置信度 |
| `context_review` | 连续语境、支持与反证相关性的复核说明 |
| `uncertainty` | 替代解释、局限与待验证信息 |
| `coverage` | 程序按支持证据重算的消息位置、日期、会话数和跨度天数 |
| `actions` | 模型填写的动作原话、逐字主体/对象指代、状态和确认依据 |
| `time_links` | 模型选取的本条引用端点，每项只含 `from_id`、`to_id` |
| `time_intervals` | 程序计算的 `calendar_days` 和 `elapsed_seconds`，附原端点 |

### 原文事实与动作判读

v3另存根字段 `source_facts`，从各条支持、反证和限制引用中复制 `evidence_id`、`message_id`、`position`、`sender`、`time`、`quote`，按来源位置排序。编译前重核逐字出处，审计时重新生成并逐项比较。报告先展示原文事实，再展示模型解释。长引文预览限160字符并标明节选，完整原话保存在账本并可回查。模型的 `kind=fact` 显示为“原话概括”。

动作格式如下。`evidence_id` 必须属于本条支持引用，`quote` 必须逐字属于该引用本身。

```json
{
  "evidence_id": "本条支持编号",
  "quote": "我准备把文件发给小林。",
  "actor": "我",
  "target": "小林",
  "state": "planned",
  "confirmation": null
}
```

`actor` 与 `target` 保存原话中的逐字人物指代，原话缺少显式指代或归属不清时填 `null`，字段显示待确认。正文中的主体与对象由复核结合发言者和上下文核验，实际存在歧义时须保留疑点。`planned` 表示计划或意向，`reported_done` 表示自述完成，`unknown` 表示状态待确认。`confirmed_result` 需要 `confirmation` 对象，包含本条另一发送方后续支持引文的 `evidence_id` 和逐字 `quote`。其余状态的确认依据须为 `null`。程序约束出处与顺序，人物实际身份、动作含义、确认是否指向同一结果仍由模型判读。

有动作的通过意见须为每项返回 `action_checks`，从1开始的 `action_index` 必须恰好覆盖全部动作。每项包含布尔值 `actor_supported`、`target_supported`、`state_supported` 以及非空 `reason`。任何一项为false都会要求修订。修订即使删去动作，也要重新复核整份结论，最终实际输入及账本保留这一门槛。缺失或矛盾记录阻止审计发布。

`actions`、`time_links` 可省略，编译时补为空数组，完整条目修订同样接受省略可选字段。纯表达风格和关系解释可使用空动作数组。模型若在正文提出动作却漏填数组，仍需语义复核识别。正常入口为所有新报告执行复核，避免遗漏动作数组绕过这一环节。复核本身仍存在漏检。

新输入增加逐字引语校验标记。中文双引号、直角引号和英文双引号中的连续文字须属于本条支持、反证或限制的某一引用，覆盖正文、解释、待确认说明和证据理由。概念及改写使用普通叙述。此规则只检查带引号文字的字面出处，未加引号的复述及动作含义继续依赖语义核查。历史输入按其原标记审计。

### 时间计算范围

日期、钟点及量化间隔通过 `time_links` 表达，程序按导出时间字符串计算日历日差和实际秒差。跨午夜两分钟可以同时显示相隔1个日历日和120秒。缺失或无法解析的时间保留 `null`。倒序、同一物理消息和重复端点组合会被拒绝。消息间隔与事件关联分别核验。

叙述字段的词面规则拒绝常见明确日期、钟点、数日后、次日等表述，包括存疑结论及证据理由。text、context_review、uncertainty和证据reason即使复述原话，也须改为定性说明。原话时间保留在actions.quote及程序展示的引文中。time_links计算被引用消息的发送间隔，未来意向的执行时间须另有依据。这套规则覆盖有限表达形式，其他时间说法及跨事件拼接仍需语义核查。

## 强制校验

- 支持、反证和情境限制必须属于当前快照、本次入选材料，且能重新匹配逐字原文；未知、隔离和存疑条目不能充当事实依据。三组编号不能重复或重叠。
- 每条反证须有非空 `reason`，`target` 须原样出现在当前结论 `text` 中；情境限制单独解释适用的时间、场景或条件。无关材料不引用，不要求每个判断都找到反证。
- 除存疑外必须有支持证据。存疑固定为低可信度、局部范围，保留明确的不确定性。
- 推断、假设及跨时间模式的全部引用必须进入完整窗口目录：每个锚点基准邻文及边界轮次均已展示，所属候选单元也未因预算截取。只展示局部出处或只出现锚点不算完整；局部事实可仅引用已匹配原话。结构完整不证明已识别完整话题。
- `subject=peer` 的非存疑结论须包含对方发送的支持引文，用户自述不能单独支撑对方人物判断。
- 重复模式至少有两个不同日期的独立会话；长期模式至少三个日期、三个会话且跨度达到 30 天。会话按四小时间隔切分。反证和情境限制的时间不计入支持范围，重复引用同一消息不增加覆盖。门槛用于阻止范围夸大，不用于计算关系分数或证明稳定人格。
- 有反证编号时状态须为 `found`；无反证时明确区分“本次入选材料未找到”与“尚未判断”。非存疑结论必须完成这项复核。
- 叙述字段只接受纯文本，P短编号和E/M/C稳定编号均放在专门引用字段。程序拒绝中文紧邻编号、编号范围及理由中的裸编号，以保证报告引用统一转换并可回查。

生成指引要求解释中的动作、日期和结果也由本条引用支持。图片、文件及通话占位记录只表明该类消息出现，附件内容和执行结果保留未知。关于用户期待或投射的假设须有用户自己的明确表达。上述含义约束仍需要语义复核及原文核对。

同一条结论的多个时间表达会一起反馈。引用编号或时间端点无效时，程序同时列出该条文字中可独立识别的时间错误。重复、角色重叠及未知引用反馈具体编号和字段位置，检索路径优先使用P短编号。初稿及修订纠错均提供本条已登记且可用的时间端点，旧E引用沿用编译器的重核映射。模型可补充其他入选引用，或将无须比较的time_links留空。作者明确提出的后续建议可增加拟议话题，复核检查其依据及效果承诺，建议本身无需作为原文动作填入 `actions`。

进入事实字段校验后，程序遍历全部动作和时间关系，反馈每个无效元素的数组位置。同一动作中无逐字依据的主体与对象会一起反馈，动作引用未登记为支持时列出实际编号。依赖无效字段的后续检查仍须等字段修复，所有问题消除后才继续发布校验。

引文已核验时，支持与限制的角色重叠不会阻止同时反馈独立的动作和时间错误。正文、语境、存疑及证据理由中的全部不匹配引语会一起反馈；进入事实校验后，动作、时间文字和引语错误也一起收集并去重，减少一次格式纠正后才暴露另一处错误的情况。未知引用或未通过原文绑定时，依赖这些引用的检查仍须等待修复。

独立来源归属提取保留为显式传入 `source_request` 的实验入口，默认工作流执行既有语义复核。实验会分批解释引用的人物和动作，逐字检查人物绑定，并在非存疑结论引用未知归属材料时要求修订。第四轮对照发现其仍会将发言者填为话题人物，因此撤下了默认调用。实验账本保存来源核查记录，可独立重审出处和输入身份。

例如，“对方表达过关心”可以由明确的关心言语支持；“今天有课不能见面”可以作为时间限制，不自动成为该命题的反证。若命题是“对方每次都会答应邀约”，一次明确拒绝则是直接反证。证据角色取决于具体命题，不从抽取账本的类别直接继承。报告分别展示反证针对的片段、理由和情境限制。

报告、来源元数据、账本和实际输入成组发布，失败保留上一组产物。独立审计重新计算结论编号、来源范围、输入哈希，并检查正文完全由该账本生成。历史v2按原字段、旧正文和兼容文字规则重审。实际输入带v3协议标记时禁止降级为v2。v1需要新建运行。流程指纹包含事实模块，重新生成使用新协议。

报告输入列出完整窗口编号及真实日期、说话人。结构校验失败时一次反馈全部失败项，并按支持证据计算真实日期、会话数、跨度、发送方及可用范围。语义修订单独保留一次机会。模型负责同时修正判断文字及标签，存疑结论固定为局部、低置信度。叙述字段使用纯文本，引用编号放入专门字段。当前阶段的纠正机会耗尽后停止发布。每次实际输入、再次脱敏的响应、合并结果与错误保存在本机 `claim_attempts_*` 目录，成功账本绑定最终实际输入。传输及截断重试沿用模型客户端规则，逐次记录用量。
