# 本地数据脱敏（2026-10-29）

## 默认行为与使用方法

网页预处理、完整分析、两个采样预览入口，以及命令行预处理默认先在本机脱敏，再生成统计、提示词、证据和报告。原始导出保持不变；网页导入副本及任务输入快照继续保留在本机的已忽略目录中。

网页“其他需要隐藏的内容”可填写第三人的姓名、住址、单位等，每行一个。最多200项，每项1至500字。新任务保存该词表，停止后继续沿用原词表；修改词表应新建任务。页面显示材料中的文本替换次数，不显示原值或反向映射；已丢弃的身份元数据不计入次数。

完整命令行支持额外词表：

```powershell
python agent/run_workflow.py 名称关键词 --redact-terms-file privacy_terms.local.txt
```

词表为 UTF-8，每行一个非空词；也可使用 `.json` 字符串数组。推荐的 `privacy_terms.local.txt`、`privacy_terms.local.json` 已加入 Git 忽略。单独的轻量预处理及旧预览入口默认执行自动规则；补充词入口以网页和完整工作流为准。

## 替换规则

| 对象 | 默认处理 |
|---|---|
| 双方昵称、备注及已提供的发送者账号 | 根据输入元数据登记，正文替换为“我/对方”；同名归属不明时使用参与者占位符 |
| 会话展示信息 | 分析侧仅保留中性角色；输出目录使用会话别名，不使用原昵称 |
| 手机号 | 常见大陆手机号及带86前缀/空格格式、国内座机和带加号的常见国际号码，替换为 `[手机号1]` 等 |
| 邮箱 | 常见ASCII邮箱，替换为 `[邮箱1]` 等，支持紧邻中文的情况 |
| 证件 | 常见大陆15/18位身份证形式，替换为 `[证件1]` 等，不以校验码有效性决定是否隐藏 |
| 银行卡 | 连续或空格/短横分组的16至19位数字形式，替换为 `[银行卡1]` 等；可能覆盖其他同形长编号 |
| 微信/QQ | `wxid_` 形式，以及带 `QQ/微信/微信号/WeChat` 标签的常见账号形式，替换为账号占位符 |
| 链接 | `http://`、`https://`、`www.` 形式，整个地址连同查询参数替换为链接占位符 |
| 补充词 | 按字面匹配，替换为 `[自定义1]` 等；不执行正则表达式 |
| 不用于分析的原始元数据 | 丢弃；原始消息编号在分析侧替换为 `source:N`，原导出中的编号仍只在本地原始文件中 |

同一值在同一对话中使用相同占位符，已生成的占位符不会再次替换。带86前缀及空格的同一大陆手机号也合并为同一占位符。日期、时间、消息数量、发送方向和原始消息序号保留；消息类型、证据编号及合法机器枚举受到保护，避免昵称与 `low` 等枚举重名时破坏格式。

同一对话的替换映射仅存于处理进程内存中，不导出反向映射文件。模型请求前再次应用当前规则；返回的结构化 JSON 先解码再处理自然语言字段，报告文本和模型错误信息也应用脱敏。分块文件保存脱敏后的结构化响应，不再保存可能带可逆转义敏感值的原始响应字符串。

## 与原文绑定、缓存的关系

脱敏发生在消息解析与证据编号之前，证据绑定指向**脱敏文本**中的字符范围。`original_index` 仍定位到原始导出中的同一条消息；脱敏会改变文字长度，不能把字符偏移直接套用到未脱敏原文。需要回查时，先根据消息序号找到本地原消息，再对照替换后的内容。

来源身份还包含规范化原始输入的指纹；即使两个不同手机号都显示为 `[手机号1]`，原始值变化仍会改变消息和证据编号。该指纹只用于输入变化检测，不包含明文映射。

规则版本、补充词指纹和脱敏后的消息进入缓存身份校验。模块升级或词表改变会使旧流程缓存失效；旧昵称目录和旧报告保留，不自动改写或删除，新运行使用会话别名目录。同一会话有稳定元数据时别名随正文变化保持稳定；缺少任何会话身份时退回输入指纹，不能保证跨版本别名一致。仅有相同昵称而无稳定账号的导出，也不能证明是同一真实对象。

## 本机仍保留什么

- `talks/` 中的原始导入副本。
- `analysis/web_jobs/<任务>/input.json` 或 `input.md` 原始任务快照。
- 同一任务 `request.json` 中用户填写的补充词。
- 本机文件列表、任务名称或命令行选取列表中的原文件名，以及已有历史产物。

这些内容仍由既有本地访问边界及 Git 忽略规则保护，不通过结果下载接口公开原始输入或词表。本轮不清除历史未脱敏报告。要获得当前规则处理的结果，应新建任务或重新运行分析；不要将本机原始数据目录整体当作脱敏结果分享。

## 局限

这是一套规则与指定词表驱动的假名化处理，不是完全匿名化。第三人的姓名、地址、单位、罕见号码、混合字符、故意拆写的身份信息及上下文间接身份线索，可能无法自动识别；需要补充词和人工检查。常用词恰好与昵称或补充词相同时，也可能被过度替换。

图片、文件和音视频内容没有解析或脱敏；当前流程只使用导出的文本/占位信息。时间线及互动内容保留，因此仍可能具有可识别性。短标识别名与输入/规则指纹使用哈希，不是加密；不能将其视为不可关联或不可猜测的匿名标识。脱敏后的文本长度统计会随替换变化，不代表原文字数。

## RED / GREEN / REFACTOR 与验证

**目标**：默认在输出/模型调用前替换已知敏感信息，保留原始输入，支持补充词，并保持证据、恢复和发布行为可用。

**RED**：新增 `tests/test_privacy_redaction.py`，执行 `python -B -m unittest discover -s tests -p test_privacy_redaction.py -q`。观察到预处理和模型提示仍含虚构身份字段、无手机号占位符、缺少补充词参数/任务配置及无效词表被接收。模型请求测试先修正了测试回调的关键字参数读取，再确认失败来自未脱敏内容。

后续边界先复现再修复：中文紧邻邮箱漏匹配、昵称破坏消息类型、转义 JSON 仍能还原原值、异常信息未脱敏、内部哈希被当作手机号、不同隐去值共用消息身份、昵称与置信度枚举重名导致证据被拒绝，以及错误时间戳对象携带原始身份键。错误类型的时间戳对象丢弃为无效值，不保留其中任意私密字段。

**GREEN**：独立 `privacy_redaction.py` 负责规则、占位符、词表校验和任务上下文；预处理在落盘前调用，报告调用共用请求/响应脱敏。词表保存到网页任务请求并参与缓存身份，完整CLI增加词表文件参数。

**REFACTOR**：新会话别名不再依赖正文，保留输入变更的恢复校验；原有恢复/预览测试从产物 API 取得目录，不再写死昵称路径，保留原有保护断言。
