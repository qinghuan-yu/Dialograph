## 五分钟演示

需要 Python 3.10+，检索依赖 Python 自带 SQLite 的 FTS5 `trigram` 支持。生产代码使用 Python 标准库，网页无需 npm 安装或构建。Node.js 只用于前端测试。

在项目根目录运行：

```powershell
python agent/web_app.py
```

浏览器打开 <http://127.0.0.1:5173>，导入 `tests/fixtures/web_smoke.json`，选择“仅预处理”，即可演示导入、进度和统计，全程不调用模型。端口占用时加 `--port 5174`。

完整分析需要将 `.env.example` 复制为 `.env`，填写自己获准使用的模型服务、密钥与模型名。网页和完整 CLI 默认“人工确认”；完整分析仍会将脱敏对话发送到配置的服务并产生用量。修改配置后重启网页服务；重复的 `.env` 键采用首次出现的值，进程环境变量优先。

```powershell
python agent/run_workflow.py 目标关键词 --review-mode human
```

关键词可能匹配多个文件；不写关键词会处理 `talks/` 下所有受支持输入。先检查选中范围，再进行付费生成。

阅读报告时，顶部“原文事实”中的对话原话默认收起，点击标题展开；下方模型解释保持展示。点击蓝色引用可回查原文，窗口在加载前后保持稳定位置，长原文内部滚动；按 Escape 或点击背景关闭。下载的 Markdown 仍保留完整原话与引用。

## 完成意味着什么

| 检查层 | 本版能确认的内容 | 仍需核对的内容 |
| --- | --- | --- |
| 输入与分块 | 格式、双方身份、消息覆盖和来源编号 | 原始导出是否包含全部相关交流 |
| 原文与结论结构 | 引文出处、引用范围、字段、时间计算及动作结构 | 谁对谁做了什么、是否完成、是否省略重要后续 |
| 报告交付 | 两份报告可阅读、下载并回查原文 | 解释是否成立、是否把局部现象扩大为长期特点 |

默认 `human` 模式不调用逐条模型语义复核，每份初稿最多一次结构纠错，不合格仍拒绝发布。可显式选 `model` 模式增加模型复核；它仍可能漏检，不能代替人工确认。

`human_review.status` 固定为 `pending`，绑定结论与输入哈希。目前没有把报告改为“已确认”的网页按钮或持久化接口；不能手改字段绕过审计。人工反馈应另存，并注明针对哪个版本、是整体认可还是逐条核对。修改报告时保留原版，不能只改 Markdown 而让结论账本与出处记录不一致。

技术接入要注意：完整 CLI 和新网页任务默认 `human`，内部 `LLMConfig`/生成函数以及缺少模式字段的旧网页任务仍兼容 `model`。内部调用应显式选择模式，切换模式会改变复用指纹。合成侧写评测是单独的付费实验，不是日常回归命令。

## 代码与数据地图

```text
输入适配与脱敏
  → analysis_service：CLI/Web 共用运行决策
  → chunk_pipeline：分块抽取、原文绑定、汇总
  → report_context / claim_retrieval：选取连续原文与披露省略
  → report_generation：准备报告输入
  → claim_ledger：生成结论 JSON，调度有界纠错与所选确认模式
  → claim_compiler / claim_facts：本机校验和编译
  → 渲染正文、artifact_audit 审计、run_promotion 发布
  → 网页阅读、引用回查及 Markdown 导出
```

关系报告和人物侧写分别暂存、审计和发布。异常可回滚，不承诺断电事务或多写者并发；同一对象串行运行。完整分块覆盖不意味着最终报告看到了全部原文，须查看选材覆盖与省略记录。默认报告原文预算仍是 48,000 字节；完整原文模式需要显式配置。

网页任务位于 `analysis/web_jobs/{job_id}/`；CLI 报告位于 `analysis/`，运行材料位于 `analysis/临时文件/{会话别名}/`。保留任务的输入快照、账本、报告输入、来源元数据和状态，才能审计及回查。网页不会自动导入 CLI 历史。

原始会话、报告、模型请求与响应、数据库、`.env`、补充脱敏词及本地计划保持在 Git 忽略范围内。分享队友时优先提供公开代码、指南与合成样例；私人结果需按其数据授权单独处理。

## 清空最近任务与恢复

网页“最近任务”来自服务启动时读取的 `analysis/web_jobs/*/state.json`，目前没有网页删除入口。需要清空列表但保留报告时：

1. 确认没有排队或运行中的任务，停止网页服务。
2. 将整个 `analysis/web_jobs/` 移至本机 `analysis/web_jobs_archive/<归档时间>/`。保留完整任务目录，包括输入、状态、账本、报告及来源文件。
3. 重启服务。程序会创建空的 `analysis/web_jobs/`，刷新网页后列表为空；`talks/` 原始对话和独立保存的 CLI 报告不受影响。
4. 如需重新阅读归档报告，先停止服务，将对应 `{job_id}` 目录恢复到 `analysis/web_jobs/` 后重启。遇到同名目录先核对版本，避免覆盖。

归档仍属于私人材料，不加入 Git。仅移动磁盘目录而不重启服务，不会清空已载入内存的任务列表。

需要清理整个工作区时，可在停止服务后，将 `talks/`、整个 `analysis/`（包含之前的网页归档）和本地过程记录按原相对路径移至仓库外的 `../dialograph归档/<归档时间>/`。先记录文件清单和哈希，移动后逐项核对；恢复时按同一路径放回，避免覆盖新数据。`.env`、本地启动脚本及正式 `tests/` 回归保留，可重建的测试缓存单独清理。

## 修改后的验证

在项目根目录运行：

```powershell
python -m unittest discover -s tests -v
node --test tests/test_web_evidence_ui.js
node --check frontend/app.js
node --check frontend/report-markdown.js
```

回归使用合成数据和模型替身，不调用真实模型；HTTP 测试需要本机回环访问和临时文件写入权限。2026-11-07 的人工确认版本基线为 417 项 Python、33 项 Node 测试；2026-11-08 的阅读体验修复增加4项 Node 回归，前端合计37项通过。数量仅作版本记录，后续以实际输出为准。若旧 `.venv` 启动器指向不存在的解释器，先使用可用的 `python` 检查版本，不必为了运行标准库程序安装实验依赖。

清理时保留 `tests/` 中的回归和合成夹具、正式报告的整套来源材料，以及付费实测的原始响应、失败和用量记录。可以清理经确认无在途任务的字节码缓存、可重建测试索引和独立合成工作区，先记录具体路径及恢复来源。不要因目录名含“临时文件”就整目录删除。

后续维护按实际使用问题安排；选材职责拆分、统一实验入口和自动语义准确率研究另行排期，不默认继续消耗模型预算。
