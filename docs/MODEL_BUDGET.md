# 模型用量与缓存

完整分析会在当前对象的临时文件目录保存两份用量文件，网页任务位于 `analysis/web_jobs/{job_id}/output/临时文件/对话_*/`，CLI 位于对应输出目录的 `临时文件/对话_*/`：

| 文件 | 内容 |
|---|---|
| `model_usage.jsonl` | 每次实际 API 请求一行，含阶段、批次/分块、操作编号、尝试次数、用时、输出上限、结束原因与服务返回的 token 计数 |
| `model_usage_summary.json` | 累计用量、按阶段和模型汇总，以及最近一次完整分析调用的用量 |

阶段为 `extraction`（抽取）、`merge`（合并）、`analysis`（关系分析）和 `persona`（人物侧写）。同一操作内的重试逐次计数；缩块重跑和后续恢复会追加记录。完整复用已有报告时，最近会话请求数为 0，历史累计不会重复计入。用量文件保存在本机，不包含提示词、聊天正文、模型正文、密钥或服务地址；已有历史任务不会补造用量。

触发命题检索时另记录 `review_plan`，独立复核记录为 `semantic_review`。首次顺利完成两份检索报告需要规划1次、生成2次、复核2次。每份报告有一次初稿格式纠错、一次语义修订及一次修订格式纠错，最多4次生成与2轮复核。每轮复核响应另有一次协议纠错，因此每份报告最多4次复核请求，双报告加规划最多17次逻辑调用。实际次数受规划缓存及客户端传输、截断重试影响。串行实测可用 `llm_usage.BoundedRequests` 在传输前持久计数，失败占额度，重启沿用同一额度文件。正常工作流沿用模型客户端的重试策略。

## 如何读统计

`LLM_MIN_OUTPUT_TOKENS` 是显式输出预算下限，默认0。每次请求取阶段预算与此值的较大者，实际传输额度记录在 `max_tokens` 中。思考模型可按服务能力设置，例如24,000。初始额度不超过8,000时沿用8,000的截断重试上限，更大的初始额度可重试至其两倍。同一请求最多尝试三次。未完整接收响应的连接中断按瞬时错误重试原输入，用量缺失时记录未知。带完成标记的旧报告入口遵循相同预算规则。

MiMo本轮19次实测已知输入791,832、输出193,097，合计984,929 tokens。17次返回用量，1次连接中断及1次用户要求停止时的中断缺少服务用量，金额待账单核对。试运行设置最低输出额度24,000，整份关系报告复核截断后以48,000重试，成功响应实际输出34,644 tokens，其中思考32,131，耗时约11分钟。较大的预算支持继续复核，也增加等待与可能用量。完整双报告内容验收尚待完成。

v3非检索路径的全部新报告也执行语义复核。顺利完成两份报告需要生成2次、复核2次，含动作时逐项检查。计入全部格式纠错与语义修订后，双报告最多16次逻辑调用。客户端传输与截断重试另外计数。

原文事实复制与时间计算在本机完成。说明已压缩并通过原有输入预算回归。v3首轮12次真实请求合计输入384,983、输出20,423、总405,406 tokens，含未通过结构或语义校验的响应。正常入口前两次尝试在结构校验阶段停止，最后一次新增6次并复用1份完全相同的初始响应，完成关系报告，人物草稿在独立复核前耗尽额度。实际账单金额待核对，成本与成功率仍需结合未完成验收评价。

- `prompt_tokens`、`completion_tokens`、`total_tokens` 使用响应中的实际计数。输出计数包含服务定义的生成 token；`reasoning_tokens` 单独记录其明细，不再叠加到输出总数。
- DeepSeek 的 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` 分别表示命中和未命中的输入。也支持兼容服务的 `prompt_tokens_details.cached_tokens`；输入总数与命中数均已知时，可相减得到未命中数。
- 没有返回的计数为 `null`，不会用输出上限 `max_tokens` 估算。`known_requests` 给出每个字段实际已知的请求数；部分已知时，总数仅汇总已知请求。
- `cache_hit_rate` 仅统计命中数、未命中数均已知的请求；同时查看 `cache_measured_requests` 和 `cache_unknown_requests`。无可统计输入时比率为 `null`。
- `usage_unknown_requests` 标出缺少输入或输出计数的请求。超时等失败可能已经产生费用，应结合服务账单核对。
- 截断、返回不可用正文等尝试只要已经返回 usage，就会保留其用量；传输失败但未拿到 usage 的请求列为未知。`failed_requests` 指请求或正文处理失败次数，报告缺少完成标记、证据格式错误等后续校验可通过同一操作的多次请求和工作流日志核对。

## 公共前缀

抽取提示词先放固定规则和五类证据格式，再放变化的分块编号、时间、消息数量与聊天原文；合并提示词先放要求和章节结构，再放对象、批次和材料。

发送给模型的消息头使用块内短编号 `m1`、`m2` 等，并将同日消息的日期提取到 `=== YYYY-MM-DD ===` 公共行，消息行保留精确到秒的 `HH:MM:SS`、发送方和逐字正文，可由 `expand_compact_transcript` 无损还原。返回后按本块显式映射回完整消息编号，再执行逐字引文绑定。相同短编号在不同块指向不同消息；未知、格式错误或多来源提示仍按既有规则隔离，不做猜测。持久账本和缓存保存完整编号与完整时间字符串。

分块规划继续预留完整编号与完整日期的字节预算，短编号与公共日期行只减少实际发送量，不自动扩大每块消息范围或降低证据条目配额。条目上限与输出预算不变。摘要保留已核验的引文发言者；用户自述不作为对方的直接人物证据，条目仍完整保存在账本中。

关系分析（`analysis`）与人物侧写（`persona`）共用统一的系统提示词（`report_framework.build_report_system_prompt`），按固定次序完整包含两份实际技能框架和来源/归属约束。两份报告发送相同文本，复用指纹也覆盖实际合成结果。前置公共材料按相同字节顺序排列，报告专属任务及输出协议置于尾部。检索路径的公共材料由固定说明、基础统计、全量覆盖说明、完整入选会话和检索覆盖计数组成。非检索路径另有结构化证据摘要、阶段总结与核验目录，人物侧写附加最多2,000字节的关系报告二手线索。

DeepSeek 自动管理缓存，匹配的是输入前缀；可以用响应中的缓存计数核对效果，见[上下文缓存官方说明](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)。公共前缀变长只表示增加了复用机会，字节数不是 token 数，也不等同于已实现的费用节省。缓存命中仍取决于实际请求与服务状态。`summary_merge.py` 另提供未接入正式流程的本地聚合实验；每条关系、人物和反证记录只在一个章节输出。比较工具仅记录格式中可见的编号、日期和小节，明确返回 `semantic_preservation=not_evaluated`；LLM合并未要求保留编号，编号为零不能证明其丢失跨时间语义。

提示词排列变化会改变流程指纹。已有完成报告仍可阅读；需要重新生成时会按新流程创建兼容运行，旧流程缓存不会强行续跑。当前用量记录覆盖网页和完整 CLI 共用的分析入口，单遍预览脚本不生成这份账本。

## 报告材料预算与原文窗口

非检索路径的结构化证据预算为24,000 UTF-8字节，阶段材料为12,000字节，人物侧写关系报告线索最多2,000字节。检索路径移除这些二手材料，直接使用完整入选会话。两条路径的原文上限均为48,000字节，统计、覆盖说明单独限长。检索路径的全量同文计数另有4,000字节上限，选材完成后生成，优先展示长文本并列出省略数。实际token用量与费用需查看usage及账单。

当账本包含已核验分块文档时，系统先从完整脱敏账本构建**候选事件单元**（`CandidateEventUnit`），再由同一份候选事件单元选择结果同时决定结构化证据摘要（`evidence_summary`）与连续原文窗口（`source_context`），消除多级独立筛选各自丢弃后期关键材料的断层：

- **结构聚类边界**：按物理消息来源（`message_id`）去重锚点，同会话内相接的基准窗口组成候选单元，不再用65条、5400秒等额外阈值拼接，也不把位置顺序命名为起因、转折或结果。结构聚类不能证明同一话题或完整事件弧。
- **物理指标与待复核标签分离**：单元分别记录物理指标与待复核的类别/方向标签。多锚点队列仅按不同来源消息数、发言轮次及消息跨度排序；类别数量、方向共现和 `confidence` 均不参与优先级。
- **超预算单元范围缩小与短互动保留**：只依据实际字节预算选择，不设76条或0.78预算比例的隐藏上限。超预算时可按空间分布展示局部窗口并记录省略锚点；明确标为“范围缩小，非完整事件”，整组编号不进入推断可用目录。时间轴四段保留多锚点与单锚点队列，先给短互动选择机会。
- **存疑单独保留**：`uncertainties` 没有事实级原文锚点，单独保存在存疑轨道并按预算装入摘要的“存疑问题”章节，绝不伪造消息来源或混入 `context_ids`。

证据按实际条目大小装入预算，不截断编号、引文或判断。完整窗口入选编号及范围缩小单元的省略编号优先装入摘要，其余条目按类别、方向与时间轴轮流补充。摘要记录上游选取/隔离数量、本次各类别入选数量及时间轴四段的候选覆盖；这是材料选择覆盖，不是对全部对话的判断正确率。

阶段材料独立识别 `## 阶段总结` 批次和 `## 结构化证据摘要`。过长时均匀选择最多六份材料，再按完整表格、段落、列表项、代码块分配预算，记录选取数量；不再只保留无序列表行，也不把多批章节误当成一份证据类别。

每个入选锚点以前后各16条为基准，向外补齐边界发言轮次，因此可能超过33条；会话边界、相邻间隔超过四小时或未知时间会截止。锚点多时也不缩短基准窗口。重叠窗口自动合并，完整目录要求整个候选单元的基准窗口均被展示；局部出处仍可供核查，但不获得推断资格。绑定不一致会拒绝生成，隔离或未知编号不能借回填进入证据，存疑不伪造原文。

实际关系报告输入保存为当前 run 的 `report_input_analysis.md`，人物侧写输入保存为对象临时目录的 `report_input_persona.md`。它们含脱敏会话原文，只在本机保留，与 `analysis/` 一同忽略，不进入 Git 或公开附件列表。

完整报告返回结论JSON，由程序校验并渲染。使用命题检索时增加独立语义复核，输入包含生成阶段可见的全局统计、覆盖记录及原文。提示通常选择6—10条有独立依据的关键结论，结构与语义分别限次纠正。语义修订完整替换失败条目，合并后复核全部结论。所有请求计入用量，实际成本需结合重试记录与服务账单核对。详见[结论账本](CLAIM_LEDGER.md)。

第四轮的独立来源归属提取实验按每批最多16个引用位置请求模型，每批最多修正一次，同一份报告修订时复用已核验位置。其真实对照未建立可靠的归属判断，已撤下默认调用。显式实验调用计入 `source_review` 用量。

完整 JSON 不再依赖额外完成标记：服务正常结束且正文完整时，直接进入逐条校验；真实截断仍拒绝并按原策略重试。纠正提示会列出支持证据的实际覆盖和发送方，减少模型重复计算错误。不能把反复重试产生的高缓存率当成降本，需同时比较实际请求数与未命中输入总量。

模型辅助事件导航及扩大到全部候选原文窗口仅做过本机对照，未接入默认流程。导航实验仍发生关键过程遗漏，完整窗口对照也仍有反证相关性问题；前者新增选材请求，后者显著增加首次输入。两者均未作为已验证的预算优化发布，默认原文预算仍为48,000字节。

命题驱动检索已条件接入默认工作流。规划读取完整脱敏原文，当前主样本规划用户输入为562,404字节，最终选材原文为45,598字节。规划阶段尚未实现超长来源的分段处理。新增规划、复核与纠正会增加费用，本轮按报告质量进行验收，成本优化仍需单独对照。
