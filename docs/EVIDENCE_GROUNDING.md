# 证据编号与原文绑定（2026-10-29）

## 当前行为

完整工作流现在为解析消息分配编号，并在模型输出结构校验后，逐条核对事件、关系信号、人物信号和反证中的 `evidence`。只在本分块的文本消息或引用消息中查找连续、逐字一致的原文；不模糊匹配、不修正标点、不拼接不同消息，也不将媒体占位符当原话。

模型可以提供 `source_message_ids: ["M_..."]` 指明唯一来源，编号从分块提示中的消息头复制。未提供时，只有整块恰好一个文字位置匹配才接受；相同原话出现在多条消息、引用正文或同一消息的多个位置时均标为歧义。当前不支持用字符偏移消除同一消息内的重复歧义，应选择更长的唯一连续引文。

| 状态 | 意义 | 是否进入报告的证据材料 |
|---|---|---|
| `matched` | 找到唯一逐字位置，且来源属于本块 | 是；仍需判断解释是否合理 |
| `unmatched` | 无原文、来源编号无效或属于其他分块 | 否；保留在隔离清单 |
| `ambiguous` | 有多个文字位置，无法唯一定位 | 否；记录总数及最多20个候选位置 |
| `not_applicable` | 存疑问题，不属于有引文支持的事实 | 仅作为存疑，不能升级为事实 |

结构错误仍按既有规则重试或失败。结构合法但原文未匹配的条目不会令整个任务失败；系统隔离这些条目，并在审计、CLI 和网页任务结果中显示警告。全部条目均未匹配时，报告只能依据统计、明确的存疑和剩余可用材料；本轮没有对报告内容做结论级强制验证。

## 编号与稳定范围

- `source_id`：`S_` 加规范化输入的 SHA-256；覆盖会话元数据和全部适配后的原始消息，含被跳过的系统消息。
- `message_id`：`M_` 加 SHA-256 的前32个十六进制字符；绑定快照、原始序号、导出消息编号（若有）、发送方、时间、类型和内容。
- `evidence_id`：`E_` 加 SHA-256 的前32个十六进制字符；绑定快照、证据类别、契约字段及重算的原文绑定。模型自行提供的编号或绑定结果会被覆盖。
- 同一份规范化输入、相同条目和相同来源位置，在不同路径、run、条目顺序和分块大小下保留编号；同一块内完全相同的条目按编号合并。
- 原文、消息顺序、会话元数据改变会产生新的快照编号；条目文字、置信度或来源改变会产生新证据编号。歧义条目的候选范围还受分块影响。系统不声称跨重导出、跨输入版本或模型改写后仍是同一编号。
- 相同时间、发送方和文字的重复消息仍按原始序号区分，不按内容去重。哈希编号不等于脱敏或加密。

## 账本字段与位置约定

结构化证据总表升级为 `schema_version: chat-evidence-v2`、`grounding_version: literal-grounding-v1`。模型抽取时仍可输出既有五类字段，绑定与升级由本地程序完成。

账本新增 `source_id`、`source_messages` 和 `grounding_issues`；`documents` 保留所有条目，每条含 `evidence_id`、`category`、`grounding`。未匹配及歧义条目另外集中列于 `grounding_issues`，供人工回查。每块 `grounding_stats` 统计四种状态。

匹配条目的 `grounding.source_refs` 给出：

| 字段 | 位置约定 |
|---|---|
| `message_id` | 程序分配的消息编号，可在 `source_messages` 中查找 |
| `source_message_id` | 导出方的消息编号，若输入提供则保留；Alpha 为导出内序号 |
| `original_index` | 适配后原始消息数组的零基序号，包含被跳过消息的位置 |
| `position` | 排序后有效消息的一基位置，对应分块覆盖范围 |
| `sender` / `time` | 解析得到的 `me/other` 和原始时间文本，独立于模型描述 |
| `start` / `end` | 消息 `content` 中的零基字符偏移，左闭右开；按 Python 字符索引，不是 UTF-8 字节偏移 |

可以用 `source_messages` 中对应消息的 `content[start:end]` 核对引文。多行文本保留实际换行。引用消息的正文可能包含转述或被引用者的话，`sender` 只表示该条消息的发送方，不证明引用内容由谁最初说出。

后续脱敏更新已默认在编号和匹配前替换敏感内容：当前字符偏移指向脱敏后的 `content`，原始消息序号仍可回查本机导出；不能把脱敏字符偏移直接套用到未脱敏原文。原导出消息ID在分析侧改为 `source:N`，输入原始值变化仍通过指纹改变来源身份。详见 [脱敏说明](PRIVACY_REDACTION.md)。

## 报告、恢复与审计

证据摘要只选取已匹配的引文与单列的存疑；未匹配及歧义条目只显示隔离数量。阶段总结也从这份过滤后的材料生成，避免通过原始模型响应重新引入隔离条目。分块抽取结果保存在 run 的 `chunk_*.md`，供排查，不作为后续报告材料直接传递；脱敏轮次后保存的是脱敏规范化对象。

摘要展示证据编号和消息位置。关系与人物报告提示要求引用 `evidence_id`，并明确逐字匹配不证明解释成立；模型是否遵守引用和结论支持规则，仍由后续结论账本工作解决。脱敏轮次后，分块文件保存脱敏后的规范化抽取对象，不再保存可能含可逆转义原值的原始响应字符串。

独立审计重算消息编号、条目编号、文字位置、类别、计数、隔离清单和分块覆盖。完整工作流还将账本消息索引与当前输入的解析结果比较；续跑在改写运行记录前重算缓存条目的绑定。损坏或被改动的锚点会拒绝复用。独立审计只持有账本时只能检查内部一致性，不能证明一份同时被整体改写的账本就是原始导出。

旧账本可由独立审计读取，但会提示未核验原文；当前完整工作流不能将旧账本当作新绑定结果使用。流程指纹包含新模块，旧流程缓存须新建运行，不强行续跑。已有报告、原始导出与 `.env` 没有在本次开发中被重跑或修改。

网页仍通过“结构化证据”查看和下载 JSON；本轮未增加新的结果标签或逐条消息浏览器。SQLite 检索、结论账本、语义验证、数字事实校验和跨版本身份映射继续留在后续阶段。

## RED / GREEN / REFACTOR

**目标行为**：相同快照和条目获得可重复编号，精确引文绑定到具体消息，未匹配和歧义材料不进入报告，缓存与审计能够发现绑定不一致。

**RED 测试**：`tests/test_evidence_grounding.py`。执行 `python -B -m unittest discover -s tests -p test_evidence_grounding.py -v`，初始8项中7项失败：缺少消息/证据编号、无位置绑定和歧义状态、无隔离警告。最初的编号稳定测试因为空结果误通过，补充“必须匹配两条”的断言，避免空集等于空集的无效验证。

后续先验证当前账本降级为旧版本仍被接受、报告缺少引用规则两项失败，再补最小修复；损坏范围为数组时复现审计 `AttributeError`，补充字段与计数校验后恢复通过。这些失败分别证明行为缺失或边界缺陷，没有以导入缺失作为 RED 依据。

**GREEN 实现**：新增 `agent/evidence_grounding.py` 集中处理编号、逐字匹配、隔离和重算校验；解析器、工作流和审计只负责调用。没有增加真实模型请求。

**REFACTOR**：阶段总结与最终摘要复用现有摘要函数的过滤逻辑；缓存和独立审计共用同一绑定重算规则。保留既有恢复预检和发布回滚边界，不迁移整个工作流。

**最终命令**：`python -B -m unittest discover -s tests -q`。本轮15项新增测试，全项目 **103项通过**；包含原有 HTTP、恢复、结果复用和故障发布测试。另检查 Python 语法、前端语法、UTF-8/BOM/换行和差异。全部测试使用合成数据与替代模型响应，未发送私聊或调用付费模型。
