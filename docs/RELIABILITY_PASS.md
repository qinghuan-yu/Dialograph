# 可靠性改进轮次：2026-10-17

## 目标与执行判断

Go：已有可复现问题和明确验收条件。让本地结果不会因预览、批处理或不一致的续跑缓存而被覆盖、删除或错误复用；让无效输入和无效证据在生成报告前明确失败。

## 范围与规则

- 推进长期计划 Phase 5（预览降级），补齐恢复和校验边界，为 Phase 1/2 准备可靠输入。
- 保持现有 WeFlow 私聊与完整分析入口；本轮不引入 canonical/JSONL/CSV，也不实现 RAG、claim ledger 或人格准确率调优。
- 原归档与 `.env` 不修改、不上传；测试只使用合成数据，不调用真实模型。
- 先编写并观察失败测试，再实现最小修复；新责任放入专门模块。
- 旧缓存缺少输入/流程校验信息时明确要求重新运行，不猜测兼容。

## 阶段和验收

1. **结果保护**：预览统一写入独立目录；一键入口保留现有所有结果；空工作区审计友好退出。
   - 验收：预览运行后正式报告字节不变；批处理无结果删除逻辑；空目录审计不抛异常。
2. **恢复一致性**：CLI/网页共用参数恢复；绑定输入及流程指纹；复用块时核对消息范围。
   - 验收：缩块后续跑使用保存参数；输入被修改、旧元数据或错位块在覆盖缓存前拒绝；同输入恢复不再请求已完成块。
3. **输入与证据契约**：CLI/网页拒绝缺失归属和可识别群聊；证据要求五个列表及条目结构，允许明确空证据。
   - 验收：缺 `isSend`、非法类型、多人身份、`{}` 或错误证据类型不能静默通过；普通有效私聊和空信号对照保持可用。
4. **覆盖透明与验证**：结构化摘要跨块取样并列出总数/入选/省略数；审计给覆盖缩减警告；补充最终请求瞬时失败重试。
   - 验收：后部块进入有限摘要，完整账本不减少；截断可见；瞬时错误重试，非瞬时错误不重试。

## 风险与停止条件

媒体与不带可靠发送者信息的数据不做猜测；证据校验不声称能验证推断真实性。若严格校验与合法合成数据冲突，先定位契约，不放宽到静默接受。模型预算配置、原子提升、稳定证据 ID 和数字事实核验继续留在后续范围。
