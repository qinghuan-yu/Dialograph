# 本地证据检索

网页和命令行的关键词查询在本机运行，提供账本导入、中文查询、证据编号回查及网页查询面板。报告生成另有命题驱动的选材链路，默认交付待人工确认的草稿，可选额外模型复核。

## 报告的命题驱动检索

完整工作流在初始报告材料未覆盖候选锚点所需邻文时调用 `claim_retrieval.py`。模型先阅读完整脱敏原文，提出最多8个待复核命题及支持、挑战两个方向的字面短语，再从当前账本的原文及已绑定描述中检索并重组材料。每个方向最多8条短语。查询方向仅用于发现候选过程，证据角色在具体结论下另行复核。

检索扫描已加载账本，按命题归一化词面区分度。同一命题中命中集合相同的短语合并计权，同一消息的重复条目按一个位置计数。隔离条目的描述排除出搜索范围。文本及引用消息可以直接建立原文引用，因此缺少旧抽取锚点的会话也能入选。

按四小时间隔边界回填完整会话，保留秒数、发送者和连续正文，预算为48,000字节。选择器把每条查询命中的全部可引用会话作为候选组，按命题内已完整覆盖查询的区分度占比均衡选择。重叠会话只计一次字节。每种命题覆盖组合保留质量最高与成本最低的候选各8项，最终重新核算实际渲染字节。该有界搜索保留完整候选组，预算不足时整组跳过，其他查询的入选会话仍可能顺带覆盖其部分命中。选材策略记录为 `complete-query-balanced-v3`。`covered` 表示至少一处命中的完整会话可见，`all_hits_included` 记录全部命中是否可见，`status` 区分零命中、完整入选、部分入选、预算省略与缺少可引用文本。

本地保存查询、命中位置、实际入选位置、会话边界与账本指纹；报告输入另留最多4,000字节的覆盖说明。两份报告可用相同查询构建相同公共材料前缀；计划缓存绑定账本、实际规划输入、模型和系统框架。最终结论仍受[结论账本](CLAIM_LEDGER.md)校验。

报告生成材料只展示检索覆盖计数，完整待复核命题与查询保留在带指纹的来源记录中。检索报告直接引用原文行的 `P_序号`，编译为稳定 `M_` 编号，旧摘要解释和阶段散文从该生成路径移除。人物侧写独立阅读同一批完整会话。原样重复文本附带全源及本发送方次数，包含未入选会话。计数说明在选材后生成，独立限长4,000字节，长文本优先并记录省略数。次数按脱敏文本逐字相等计算，其情绪含义仍需结合具体语境判断。

检索后的两份报告始终经过出处与结构审计。默认人工模式发布待确认草稿，模型模式另要求分别通过独立模型复核。当前选材在同源6个固定案例中完整覆盖4个。第三轮曾将同文计数放进原文预算，覆盖降到3/6，收尾已通过独立预算恢复4/6。两次正常入口完成了自动双报告发布，逐条核对仍发现重要语义误读。完整原文规划会增加输入成本，超长来源的分段规划、角色一致性及自动内容验收仍待完成。

## 网页查询

运行 `python agent/web_app.py`，选择已完成的完整分析任务，展开“查找对话线索”并输入关键词。各类别分别返回最多 5 条；可按“回查原文”查看脱敏消息全文、引文高亮、发送者与时间，并可展开来源位置。页面序号从 1 开始，接口的 `original_index` 从 0 开始。仅预处理及未完成任务不提供检索。

网页通过带本地令牌的 `POST /api/evidence/search`（`id`、`query`、可选 `limit`）和 `POST /api/evidence/show`（`id`、`evidence_id`、`revision`）查询。服务端根据任务记录选择账本、输入快照和补充脱敏词，客户端不能指定路径、数据库或开启隔离条目检索。接口遵守现有 Host/Origin 限制，不返回原始输入路径或补充词。

首次检索会将实际任务快照按保存的脱敏规则重新核对，并在任务 `retrieval/<revision>.sqlite3` 建立派生索引。索引先暂存再原子发布；同一服务中的并发查询共用构建结果。版本绑定账本字节、原输入字节/格式及补充词；任一改变后旧回查请求被拒绝。重新检索只有与当前快照核对通过才返回结果。切换任务、重新查询会丢弃页面上尚未返回的旧响应。

旧 v2 账本可用网页保存的输入快照与词表在本机重核，无需改写原账本或调用模型；缺少任务快照、缺少有效绑定或版本不一致时明确报错。已有命令行输出不会自动成为网页任务。该索引仍是本机敏感派生资料，由 Git 忽略。

## 入库与查询

先运行完整分析，找到该对象支持目录下的 `结构化证据总表_*.json`。以下路径中的会话别名请替换为实际值：

```powershell
python agent/evidence_store.py ingest "analysis/临时文件/对话_xxx/结构化证据总表_对话_xxx.json"
python agent/evidence_store.py search "修复意愿" --db "analysis/临时文件/对话_xxx/evidence_store.sqlite3"
python agent/evidence_store.py search "压力撤退" --db "analysis/临时文件/对话_xxx/evidence_store.sqlite3" --limit 5
python agent/evidence_store.py show "E_替换为实际编号" --db "analysis/临时文件/对话_xxx/evidence_store.sqlite3"
```

`ingest` 默认在账本旁创建 `evidence_store.sqlite3`，也可显式指定 `--db`。默认输出位置位于已忽略的 `analysis/`；自选位置的 `*.sqlite3` 及其日志文件也由 Git 忽略。数据库保存脱敏消息和引文，仍应视为本地敏感资料。

命令输出 JSON。`search` 和 `show` 可额外提供 `--ledger 当前账本路径`，核对数据库是否仍对应当前账本的输入快照和脱敏规则。读取缺失数据库只报错，不自动创建空库；参数或校验错误返回状态码 2。

## 旧 v2 账本

新流程账本附带 `redaction.enabled`、规则版本、规则指纹和绑定的 `source_id`。仅有 v2 编号和逐字引文，并不能证明执行过脱敏。

缺少上述信息的旧 v2 账本，可显式提供原输入，在本机按当前规则重新预处理并逐条核对已编号消息：

```powershell
python agent/evidence_store.py ingest "旧账本.json" --input "talks/原始导出.json" --db "analysis/证据库.sqlite3"
```

如果原运行使用补充词，还需提供相同的 `--redact-terms-file privacy_terms.local.txt`。此操作不调用模型、不改写原输入或旧账本，也不写额外预处理材料；只有重建结果与账本全部来源消息一致才允许导入。版本不一致时拒绝导入，不自动触发付费重新分析。不支持未绑定的 v1 账本。查询时的可选 `--ledger` 检查要求账本自带完整脱敏来源；旧账本显式重核导入后，可直接使用绑定了范围的数据库查询。

## 查询结果与来源

### 报告材料预算与完整原文模式

进入命题检索阶段的报告默认使用 `LLM_REPORT_CONTEXT_MODE=retrieval`，连续原文预算由 `LLM_REPORT_CONTEXT_BYTES` 设置，默认48,000字节。两份报告共用这些配置，变更后旧报告和流程缓存不再匹配。此预算只约束检索阶段的原文材料，实际模型请求还含指令、统计、引用和复核结构；无需进入检索的短会话仍使用原有窗口流程。

对于支持长上下文的服务，可以显式配置：

```env
LLM_REPORT_CONTEXT_BYTES=800000
LLM_REPORT_CONTEXT_MODE=complete_if_fits
```

该模式在完整脱敏快照能放入预算时保留全部会话，包括没有命中规划查询的消息。检索记录标为 `complete-source-if-fit-v1`，并列出全部会话与实际位置；原文超预算时保持原有完整查询组选材，记录实际使用的 `complete-query-balanced-v3`。默认模式不变，不自动提高预算。配置值应符合所用服务的输入容量。

完整展示只解决材料可见性，不证明模型正确理解全部内容，也不改变结论引用、动作状态或所选确认方式的检查门槛。

| 分组 | 内容 | `eligible_as_support` |
|---|---|---|
| `support` | 已唯一匹配原文的事件、人物信号和支持方向关系信号，属于支持候选 | `true` |
| `counter` | 已匹配的反证，或 `direction=against` 的关系信号 | `false` |
| `mixed` | 已匹配但方向混合的关系信号 | `false` |
| `uncertainty` | 待核实的问题，没有已证实的引文支持 | `false` |
| `quarantine` | 未匹配或存在歧义的引文，仅在 `--include-quarantine` 时加入检索结果 | `false` |

各组分别应用 `--limit`，避免支持候选占满结果、反证不可见。直接 `show` 隔离证据编号也会显示其隔离状态，不会将其升级为支持。

每条结果含证据编号、类别、原始字段、引文、绑定状态和全部出现位置。每个位置保留分块编号、消息/时间范围和唯一来源引用；引用带脱敏消息全文、发送方、消息编号、原始序号、排序位置与字符偏移。可核对 `content[start:end]` 是否等于引文。偏移针对脱敏文本，不能直接套到未脱敏原文；存疑条目没有伪造的引用位置。

## 中文匹配与排序

- 三字及以上关键词使用 SQLite FTS5 `trigram` 和 BM25 排序；也可查询证据编号、来源消息编号、分块编号和时间。
- 一至二字短词使用本地字面子串回退；该模式可能扫描本库记录，不声称具有大规模检索性能。
- 空格分隔的词要求全部匹配。用户输入按字面短语处理，`OR`、`NOT` 等不会作为查询运算符执行。
- 这是词面检索，不是语义搜索；“愿意和好”不会自动视为“修复意愿”的同义词。BM25 排名不是置信度或关系概率。
- 检索不会推断性别或关系。`eligible_as_support=true` 只表示当前来源/类别规则允许作为候选材料，不证明引文在语义上支持查询命题；报告生成另受[结论账本](CLAIM_LEDGER.md)约束，当前不从检索结果自动生成结论。

## 数据与隔离契约

一个数据库绑定一个输入快照、账本/绑定版本和脱敏规则指纹。其他快照或规则必须使用另一数据库，不能静默混入。相同范围重新导入会在一个事务中替换当前抽取，删除旧条目和旧全文索引；异常回滚旧状态。数据库不保留历次模型抽取历史。

证据编号作为主键去重，同时以“证据编号、分块编号”记录每次出现。相同存疑在多块出现只占一个证据实体，但所有出现位置均保留。所有证据在导入前重算编号、引文锚点和覆盖范围；无效账本在创建数据库前拒绝。非本程序数据库与不支持的数据库版本均拒绝覆盖。

脱敏来源字段是本地流程契约，不是签名或完全匿名的证明。原文绑定核验文字位置，不能核验心理解释、引述文字的实际作者或全部间接身份线索。请勿把数据库视为可公开分享的资料。

## 验证

`tests/test_evidence_store.py` 使用合成输入验证中文及短词检索、独立反证限额、原文位置、重复导入与多块出现、快照/词表隔离、旧账本显式输入校验、数据库写入故障回滚、外部数据库保护，以及实际 CLI 入库—查询—回查。完整分析用模型替身验证账本来源字段与空证据处理。

运行：`python -m unittest discover -s tests -p test_evidence_store.py`。需要支持 FTS5 trigram 的 SQLite；当前验证环境为 Python 3.11 / SQLite 3.45.1。缺少该功能时明确报错。

网页接口另由 `tests/test_web_evidence.py` 验证真实本机 HTTP、令牌/来源校验、任务隔离、非法路径、缓存并发构建、旧账本重核以及账本/输入/补充词变化。`node --test tests/test_web_evidence_ui.js` 验证切换任务、乱序响应、旧回查丢弃、安全文本渲染和表情符号前后的准确高亮。

## 报告引用回查

两份报告的 GET 输出接口附带 citations，其中包含 ledger_revision 及引用解析表。仅在当前已校验任务账本中唯一匹配时恢复 E_ 或 M_ 的缩写；相同前缀存在多个候选、找不到来源或属于隔离项时标记待核对。紧凑分块组会逐段展开。

POST /api/evidence/reference 接收 id、reference、revision，一次返回证据、消息或整段对话来源。消息与片段作为来源展示，保持各自的类型；存疑返回问题与原因。请求沿用任务、令牌、来源与版本校验。该回查直接使用经原输入核验的账本，无需建立全文检索库；关键词搜索仍使用 SQLite/FTS。

已有报告可直接恢复阅读和回查，无需再次调用模型。后续生成的证据摘要只提供证据编号及时间，提示词要求复制完整 E_ 编号并直接进入正文。原始报告、证据编号和来源锚点保持保存，阅读展示和脚注导出使用本地转换。
